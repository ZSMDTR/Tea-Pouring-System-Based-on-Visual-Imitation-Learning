# 空茶壶抓放：无实物阶段的检查与后续工作

检查日期：2026-10-15。当前优先目标为抓稳空茶壶、完成抬升、放回指定区域；
掉落、碰撞或人工干预均计失败。实物标准沿用20次至少18次成功。
本阶段暂停扩展倒茶、液位和随机杯功能，保留已有代码与历史记录。

## 实际完成到哪里

| 环节 | 当前实际能力 | 尚缺的抓取能力 |
|---|---|---|
| 环境与算力 | 三个隔离环境、CUDA、MotorBridge、Gemini 2 SDK、VS Code/Notebook 已检查 | 需要现场验证 USB、采流及真实反馈频率 |
| 图像获取 | Gemini 2 枚举、同步 RGB-D、对齐、去畸变、标定信息导出和 LeRobot 插件已实现 | 真实采流和相机安装/标定未验证 |
| 目标识别 | `vision.py` 使用 COCO SSDLite；`replay.py` 明确筛选 `cup` | 没有茶壶/把手识别模型，也没有茶壶抓取姿态输出 |
| 三维定位 | `geometry.localize` 用框中心附近深度反投影到 base | 这里只产生三维点；尚无夹爪方向、开口宽度、把手避让和完整 TCP 位姿 |
| 任务流程 | `planning.plan_grasp` 只返回张爪、接近、下降、闭爪、抬升五步；`MockRobot` 保存步骤 | 没有放回/释放/撤退，没有逐步执行与抓持证据检查 |
| 运动学 | 官方 RS URDF 的 FK/Jacobian 和一个邻近初值 IK 回环已验证 | IK 仍在检查脚本内；未接收抓取目标，也未实现公共关节坐标与 URDF 坐标的完整衔接 |
| 路径与碰撞 | 五次关节轨迹和限速/限加速度已实现，URDF 碰撞网格可加载 | 没有桌面/障碍物/自碰撞判定和抓取路径规划；不能从网格存在推断无碰撞 |
| 真机关节适配 | 现场配置门禁、公共度/弧度换算及单组关节目标入口已实现 | 没有从视觉到真实抓放的整条执行链，模板仍禁用实物运动 |
| 学习与验收 | 合成 LeRobot 数据、ACT短训练/重载、人工试验统计已实现 | 没有真实茶壶示教、有效抓取策略、实机策略执行或物理抓持验证 |

软件环境准备完成不等于抓取功能已经完成。当前仍有可独立于实物推进的实质软件工作。

## 本轮已直接修复的控制问题

已用延迟替代后端复现：控制器在读取反馈前获取当前时间，后端可能在读取过程中产生
更新的反馈，导致有效反馈被误判为 `future_feedback`；读取期间跨越运动超时仍可能
继续发送目标，读取期间的时钟倒退也没有被及时拦截。

`joints.py` 现在在反馈返回后重新读取并验证单调时钟，再计算反馈年龄和运动超时，
轨迹从首次有效读取完成时开始。`hardware.py` 在缺少设备侧时间戳的情况下，保守地
使用整组观测读取开始时刻，使慢速顺序读取不会把较早的关节观测标成刚刚采得。
这仍不能证明 SDK 缓存中的实际 CAN 帧年龄；现场仍须测试断线/丢帧和读取延迟。

新增5个有故障复现的回归测试，修复前全部失败，修复后全部通过：

- 读取过程中产生的有效新反馈可以启动及继续轨迹。
- 读取耗时导致过期的反馈在启动前被拒绝。
- 读取过程跨越运动超时时停止，不再发送下一条目标。
- 读取期间时钟倒退时异常终止，不发送目标。
- LeRobot 适配器的主机时间戳覆盖整组观测读取耗时。

## 不接实物还能继续完成的工作，按实施顺序排列

| 顺序 | 可以现在开发的内容 | 离线交付和通过条件 | 仍需现场确定的输入 |
|---|---|---|---|
| 1 | 完整抓放状态机与固定摆位基线 | 从当前有效状态依次完成张爪、接近、下降、闭爪、抓持确认、抬升、移回、下降、释放、撤退；替代反馈可完成全流程；任一步失败进入终态并停止发目标 | 真实关节姿态、夹爪开度、抬升高度、放置区域、实际停止方式 |
| 2 | 抓取姿态、TCP 与 IK 接口 | 明确完整位姿、单位、关节映射和工具变换；将可重复使用的 IK 从验证脚本整理成模块；覆盖多个已知可达目标、失败收敛、越限和不可达拒绝 | 实际零位/方向、TCP、相机到基座外参；六轴手臂与夹爪分别处理 |
| 3 | 路径与碰撞筛查 | 将每步位姿转换为受限关节轨迹；加入桌面/障碍物模型和自碰撞对审查；报告检查范围、采样间隔及未检查项；构造碰撞场景必须被拒绝 | 台面/底座安装、茶壶几何尺寸、夹爪占据范围及实际工作区 |
| 4 | 茶壶视觉接口及标注/训练入口 | 增加 teapot/把手夹持点接口、COCO图片与标注检查、按拍摄场次划分、训练/重载/评估入口；现有杯子检测不冒充茶壶检测 | 真实茶壶图像、把手可夹区域、遮挡和光照；有效识别精度需真实留出图片验证 |
| 5 | 相机/手眼标定辅助工具 | 建立图像与机器人位姿配对记录、棋盘角点/位姿读取、按最终安装方式选择的外参求解、独立留出样本误差报告；用合成已知变换检验数学流程 | 相机固定或随臂安装方式、标定板尺寸、真实图像和配对位姿；实测结果不能预填 |
| 6 | 全链路无运动演练与抓取专用入口 | 输入合成或录制RGB-D和明确的目标信息，输出定位、姿态、IK、关节轨迹、任务状态及故障原因；演练不创建CAN控制器；覆盖缺帧/未知外参/目标丢失/夹持未确认/超时/碰撞 | 实际设备数据与现场配置；不得自动回退到演示外参或合成反馈 |

状态机和规划器可以先使用明确标记的合成参数、替代反馈和逻辑物体状态；
实际配置中的未知尺寸和阈值仍留空。夹爪命令发送、闭爪到位和抓稳物体是不同事件，
不能由“闭爪成功”自动生成“抓持已确认”。反馈方案先留接口，再由现场确定可用信号。

第一条基线建议为固定摆位空壶抓放：先把执行闭环做好，再接视觉变化和学习策略。
它不要求先训练 ACT，也不要求先安装 ROS/MoveIt 或大型物理仿真器。
目前的轨迹、URDF 和模拟后端可直接用于上述软件开发；如果之后需要接触/摩擦仿真，
必须另行明确模型来源与参数，仿真成功仍不计为实物成功。
