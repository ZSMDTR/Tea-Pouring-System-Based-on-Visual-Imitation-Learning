# 视觉倒茶任务与实现边界

## 已确认的任务

- 机械臂为 Seeed reBot Arm B601-RS，用户已准备完整套件及相机。
- 识别茶壶，抓起茶壶向茶杯倒茶。
- 茶杯在桌面随机摆放，不使用固定的杯坐标替代视觉定位。
- 需要根据杯中液位停止倒水。
- 茶杯不透明，目标为杯子容量的90%，不是液高90%；相机接入暂缓。
- 用户希望将工程同步到自己的 GitHub。

## 工作流程

```text
识别茶壶 / 壶把 / 壶嘴，以及杯子 / 杯口
→ 构建基座坐标中的目标姿态，检查可达和碰撞约束
→ 抓壶并确认抓稳
→ 选择并持续跟踪同一个目标杯
→ 对准杯口，按反馈控制倾倒
→ 达到目标液位时请求停止并回正
→ 等待余流、复核液位，再放回茶壶
```

动作到位、夹持成功和液位可信度是不同的信号，不能互相替代。
“回正请求已发出”也不等于实际余流已停止。

## 软件已具备的基础

- 离线图片检测、RGB-D数据回放、相机到base坐标转换及mock抓取步骤。
- 官方RS模型和独立Pinocchio环境，FK/Jacobian及邻近初值IK回环已验证。
- PyTorch CUDA推理与合成训练冒烟检查通过；支持为实际任务训练模型的基础环境。
- 纯离线倒茶反馈控制模块已实现，只输出语义动作，不转换成真实关节指令。

## 必须补齐的模型与数据

现有 TorchVision SSDLite 的 COCO 类别含 cup，不含 teapot 或 kettle。
需要实际茶壶的图片/视频标注，建立壶体、把手和壶嘴定位方案；
已有模型可以作为杯子候选检测基线，但检测框中心不是杯口或抓取TCP。

液位是独立的观测任务：普通RGB能否看见液体边界取决于杯子透明度、视角和照明。
不透明杯侧面看不到内部时，需要可见杯口的视角或其他反馈来源；
RGB-D在透明/反光表面可能给出无效深度，不能把杯中某个depth值直接当作水面。
当前代码尚未从真实图像估计液位，fixture输入不代表视觉算法已实现。

建议采集：
- 实际茶壶的壶体、把手、壶嘴与不同姿态，以及手爪抓持时的遮挡情况。
- 杯子在允许区域内不同位置、姿态、光照下的RGB/深度记录。
- 空杯、不同液位、倒水中、满杯、泡沫/反光及遮挡的视频，并有真实液位测量对照。
- 杯口、液面边界或经明确定义的液位标签；不能用检测置信度充当满度标签。

## 实物接入阶段仍需确认

1. 相机品牌/型号、数量、安装位置，抓壶倒茶时能否持续看到杯口或水线。
2. 茶壶/杯子的照片、尺寸、杯子有效容量、壶装水后的质量。
3. 根据实际杯型标定液高到容量的映射；目标已确定为容量90%。
4. 多杯时倒哪一个、是否依次倒满，以及杯子允许摆放的区域。
5. 设备是否已完成零位标定、夹爪开度和TCP测量。

## 离线反馈的约定

反馈应有 cup_id、采集时间、杯位置、液位有效性、独立置信度和明确单位。
本次最小控制器采用 volume_fraction：液体体积/已标定杯容量，范围0到1，目标0.9。
它不等于液高比例，也不等于检测置信度；不规则杯型需要容量标定。
数值来自待接入的液位估计器；本轮只使用明确标注synthetic的合成反馈验证控制逻辑。

每帧还必须明确确认抓持稳定和壶嘴已对准杯口，未确认时不请求倾倒。
达到90%容量、丢失目标、过时/乱序反馈、杯子移动、身份变化或超时，都请求停止并回正；
异常终止不计为“成功倒满”，并且不会自动恢复倒水。
真实系统还必须测量相机/推理/执行延迟、回正时间及余流，提前量不能由演示阈值决定。

运行 `python scripts/replay_pouring.py` 可回放合成容量数据20%→45%→65%→85%→91%，
到91%的观测时请求stop_pour和upright；终态后即使输入50%也不会自动继续倾倒。
结果保存在artifacts/pouring-replay.json，明确标记实物容量/对准/停止均未经验证。
