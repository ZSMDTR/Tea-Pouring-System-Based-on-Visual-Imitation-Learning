# B601 视觉模仿学习：从零完成一次实验

> 适用场景：以 B601-RS 从臂、Arm 102 引导臂、相机、LeRobot 数据集和 OpenPI π0.5 为例，完成“示教采集 → 微调 → 调用模型 → 测试 → 复盘”。本文的技术依据仅选用互联网公开的官方资料；端口、相机身份、标定、关节映射和安全边界必须在现场确认。资料核对日期：2026-10-25。

## 先确定“完成”的含义

建议第一轮只选一个简单、能清楚判定成败的任务，例如“从指定区域拿起一个物体，放进容器”。在采集前写下：物体及容器允许出现的位置、机械臂初始姿态、任务指令、最长执行时间、成功条件、失败与人工中止条件。预先确定独立测试的次数和目标成功率；成功率门槛由项目自行制定，不能用训练损失代替。

本轮最终应留下五类产物：原始示范数据、清洗与划分清单、训练配置及日志、模型权重及配套归一化统计、独立测试的逐次结果与视频。能加载基础模型或得到动作数组，仅证明推理接口通了，不证明模型会完成 B601 的任务。[OpenPI 官方仓库](https://github.com/Physical-Intelligence/openpi)

## 完整工作流程

| 阶段 | 要做的事 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1. 固定环境 | 记录 LeRobot、B601 驱动、OpenPI、Orbbec SDK 的版本或提交号，以及 Python、GPU、系统和磁盘空间。选定一套相互兼容的版本；LeRobot `main` 文档对应源码安装，不能直接当作其他版本的命令。 | 软件环境可启动，版本清单可复现。 |
| 2. 准备设备 | 固定从臂和相机，确认供电、CAN、引导臂端口、停止方式与活动范围。按选定版本标定主从臂；先做小幅遥操作，逐关节核对方向，再检查两路画面和时间戳。B601-RS 使用 RS 电机与原生 CAN；文档中的端口只是示例。 | 设备身份明确、标定有效、停止机制可用、视角稳定。 |
| 3. 定义数据与模型接口 | 列出每帧的图像键、尺寸与颜色顺序，关节顺序、单位、坐标系、夹爪定义，动作频率、时间戳和任务文本。训练与推理必须使用同一套映射；两路相机还要测量丢帧和时间偏差。 | 一份可检查的 observation/action 契约，样例帧与动作能通过校验。 |
| 4. 基础模型空跑 | 下载并加载选定的 π0.5 基础模型；用符合接口的假输入或已录观测调用一次推理，检查输出形状、数值范围、耗时和归一化流程。此时只记录预测动作，不下发给电机。 | 模型能稳定返回动作，输出可被安全校验器解析。 |
| 5. 采集示范 | 用引导臂遥操作完成完整任务。每条 episode 记录相机视频、机器人状态、执行动作、时间戳、任务指令、成功/失败标签和场景条件。先小批试采并检查，再覆盖不同初始位置、物体姿态和光照；每次按同一规则重置场景。 | 视频与状态/动作对得上；有足够多的有效完整示范覆盖目标条件。 |
| 6. 质检与划分 | 逐条查看视频与轨迹，标记遮挡、时间错位、漏帧、异常动作、碰撞和中止。保留原始数据，在副本上清洗。按**完整 episode** 划分训练、验证和测试；相邻帧及同一次采集场景不要跨组。测试集在选模型前锁定。 | 有版本化的有效数据清单和固定划分；测试集未参与训练。 |
| 7. 准备训练数据 | 先核对选定 OpenPI 版本能读取的 LeRobot 数据格式；只有确有兼容需求时才生成转换副本，并核对 episode 数、字段、视频和任务文本。只用训练集计算归一化统计，保存其与数据版本的对应关系。 | 数据加载器能逐条读取，图像与状态/动作形状正确，归一化统计可追溯。 |
| 8. 微调模型 | 从基础权重开始，为本次实验保存独立配置：数据版本、随机种子、批大小、训练步数、保存间隔、模型输入/输出映射和检查点路径。先让小批数据完成读取与前后向计算，再正式训练；监控损失、验证表现、显存、磁盘和异常值。 | 训练完成，权重、配置、归一化资产和日志一同保存。 |
| 9. 离线评估与选型 | 用验证集比较检查点；最终选型后只在锁定的测试集上做一次正式离线评估。检查动作误差、输出范围、不同场景的失败类别和推理耗时。损失或动作误差只作辅助证据。 | 选出一个固定检查点，并记录其数据、配置与测试结果。 |
| 10. 接入模型调用 | 用真实录制观测重放推理请求，核对相机键、图像预处理、状态单位、任务文本、动作反变换、关节限位和过期帧处理。先只显示或记录动作；随后经现场确认，才允许安全控制器向从臂发送短动作段。 | 同一输入可复现同一接口结果；异常输入、超限动作和失联会被拒绝。 |
| 11. 实机测试 | 在人员监护下，先空场景、小幅、低速、短时测试，再按预先固定的测试条件独立重复多轮。每轮重置环境，记录成功/总次数、耗时、人工停止、碰撞或超限、推理延迟和视频。对失败按感知、数据、模型、控制和时序分类。 | 达到预设的任务成功与安全门槛；不达标则回到相应阶段补数据或修接口。 |
| 12. 冻结与复盘 | 锁定最终模型、归一化统计、数据版本、软件版本和设备配置；整理逐次测试记录与已知适用范围。若要改相机、关节映射或任务定义，应开启新实验，不覆盖本次证据。 | 其他人能重建训练、加载模型，并按同一方案复现实机评估。 |

采集规模可从小批试采逐步扩大。对“抓取物体并放入容器”这类入门任务，LeRobot 建议至少 50 条 episode、每个物体位置约 10 条，作为起点而非成功保证；实际仍要看独立测试结果。[LeRobot 实机模仿学习指南](https://huggingface.co/docs/lerobot/main/il_robots)

设备准备与遥操作顺序参考 [LeRobot B601 指南](https://huggingface.co/docs/lerobot/main/rebot_b601) 和 [Seeed B601-RS 指南](https://wiki.seeedstudio.com/rebot_arm_b601_rs_lerobot/)。相机能力与多设备配置参考 [Orbbec Python SDK](https://github.com/orbbec/pyorbbecsdk)。episode、视频、状态、动作和元数据结构参考 [LeRobotDataset v3](https://huggingface.co/docs/lerobot/main/lerobot-dataset-v3)；数据划分工具见 [LeRobot Dataset Tools](https://huggingface.co/docs/lerobot/main/using_dataset_tools)。微调、归一化和模型服务参考 [OpenPI](https://github.com/Physical-Intelligence/openpi) 与其 [归一化说明](https://github.com/Physical-Intelligence/openpi/blob/main/docs/norm_stats.md)。

## “调用模型”具体做什么

OpenPI 的官方流程是：把自有数据整理为兼容的 LeRobot 数据集，定义机器人输入/输出与训练配置，计算归一化统计并微调；完成后加载检查点，在本地或通过 policy server 请求推理。[OpenPI 官方仓库](https://github.com/Physical-Intelligence/openpi)；[远程推理说明](https://github.com/Physical-Intelligence/openpi/blob/main/docs/remote_inference.md)

以下是**接口示意**，不是可直接驱动机械臂的程序；实际字段必须来自第 3 阶段的契约：

```python
from openpi.training import config as config_lib
from openpi.policies import policy_config

config = config_lib.get_config("<与本机器人数据匹配的配置名>")
policy = policy_config.create_trained_policy(config, "<本次训练的检查点目录>")
observation = build_observation(  # 在适配层实现并验证
    camera_frames, robot_state, task_prompt
)
action_chunk = policy.infer(observation)["actions"]
validate_shape_units_limits_and_freshness(action_chunk)
# 离线阶段：只保存预测；实机阶段：由独立安全控制器逐段执行。
```

基础模型的第一次调用用于验证接口；微调后的模型调用用于评估任务。模型返回的动作通常是一段预测，执行层应按已核实的频率逐段发送，并在画面过期、通讯失联、越界或人工停止时终止。动作键、预处理和输出转换必须与训练时完全一致。[OpenPI 自定义训练与推理流程](https://github.com/Physical-Intelligence/openpi)

## 每次实验的最小记录表

| 项目 | 填写内容 |
| --- | --- |
| 任务与验收 | 成功定义、允许的初始变化、超时、独立测试轮数及目标成功率 |
| 设备 | 从臂与引导臂标识、相机角色与序列号、标定版本、停止方式 |
| 软件 | LeRobot / OpenPI / Orbbec SDK 的版本或提交号，GPU 与运行环境 |
| 数据 | 原始数据版本、有效 episode 数、训练/验证/测试划分、排除原因 |
| 模型 | 基础权重、输入/输出契约、归一化统计、训练配置、最终检查点 |
| 结果 | 离线结果、实机成功数/总次数、延迟、人工停止与失败分类 |

**对从零建立或已重置的工作台：**先完成设备绑定与现场检查，再从示范采集开始。若尚无针对本任务训练并通过实机评估的模型，即使基础 π0.5 权重能够加载，也应先完成接口空跑、微调和分阶段测试。
