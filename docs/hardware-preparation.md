# 实物接入前准备

当前软件可以离线开发、图片检测、RGB-D 回放、坐标转换、任务步骤规划、
GPU 推理及合成训练冒烟检查。合成数据上的通过不代表真实识别或抓取成功。

## 必须准备的物品和资料

| 类别 | 准备内容 | 接入时确认 |
|---|---|---|
| 机械臂 | B601-RS、夹爪、牢固底座/夹具 | 核对 RS 型号、成品套件清单及电机 ID |
| 电源与接线 | 按实际套件要求的 48V 电源、信号分离板、对应电源/CAN 线 | 由供应商确认额定电流、接口及接线；先核对套件是否已含 |
| USB-CAN | 与 Seeed SDK/原生 Linux 驱动适配的设备 | 实际固件、SocketCAN、1 Mbps、can0/can1；不能仅凭 USB 外形判断 |
| RGB-D 相机 | 同步彩色与深度、USB3 数据线、刚性支架 | 最近工作距离、视野、目标材质下深度有效性、深度对齐功能 |
| 标定板 | 已知尺寸棋盘格或 ChArUco 板 | 平整固定、实测格边长，记录单位 |
| 测试物体 | 不透明空杯，后续实际杯/壶 | 尺寸、质量、夹持位置、夹爪开度、加水后的质量 |
| 台架 | 桌面、照明、线缆固定、快速断电急停 | 相机固定，臂基座固定，工具/桌面几何可测量 |

官方页面电源信息有差异：快速入门列推荐 48V 12.5A，MIT 控制页列 48V 15A；
应按实际采购套件、铭牌与供应商要求确认，不直接据页面自行配线。
套件是否包含 USB-CAN、电源也应先核对，避免重复购买。

## 相机如何选

优先 RGB-D，先测量相机到杯子的实际距离，再确认深度工作范围及视野。
Seeed 示例涉及 Orbbec Gemini 2、RealSense D435i 和 D405，这不是任意安装距离下
兼容性或精度保证。透明/反光杯及液体可能造成无效深度，先用不透明空杯。
普通 USB RGB 相机也能采图检测，但需要已标定桌面或额外测距，不能直接从二维框
获得通用三维抓取位置。当前 replay 要求已去畸变、深度已对齐彩色的输入。

## 需要采集和填写的数据

- 相机：分辨率、fx/fy/cx/cy、畸变处理方式、深度单位、RGB/深度对齐与时间同步。
- 外参：T_base_camera，方向为相机坐标变换到机械臂基座坐标，平移单位为米。
- 机械臂：各关节零位、方向、反馈单位、限位、夹爪开度映射及 TCP/工具偏移。
- 场景：桌面高度/法向、相机和基座安装位置、障碍物及真实可用工作区。
- 任务：杯/壶类别、目标抓取姿态、夹持位置、可接受夹持力和到位容差。
- 验收集：固定测试场景、独立测试图片/深度记录、重复抓取次数和成功定义。

本项目 fixtures/calibration.demo.json 与 config/simulation.json 中的值都是合成演示，
不能用于实物控制。杯体表面三维点也不能直接当作真实 TCP 目标。

## 真机接入顺序

1. 按厂家要求固定和接线；核对成品臂 1–7 号电机在线，不盲目重写 ID。
2. MotorBridge 中选择 rebot-arm-robstride，按官方流程校零并回读参数。
3. 单关节低速空载验证，再验证夹爪开合、实际反馈、超时与停止策略。
4. 验证相机、彩色/深度对齐及内参；采集手眼标定数据，量取工具偏移。
5. 检查同一物体三维位置与人工测量是否一致，再验证姿态/IK/限位/碰撞。
6. 空杯低速抓取与抬升，记录重复成功率；稳定后才进入冷水和倒茶阶段。

## Linux 部署方式

本次沿用 WSL2 Ubuntu22.04 完成离线开发。Seeed 当前快速入门更推荐原生 Ubuntu
物理机（推荐24.04）。真机阶段可用原生 Ubuntu 或 VS Code Remote-SSH 连接控制机。
WSL USB 透传需适配器/相机到位后验证，不把透传成功等同于控制稳定。
无需现在安装 USB 转发服务或修改 Windows 驱动。

ROS Humble 已保留并可独立使用；本项目暂不将系统 ROS 的依赖混入视觉虚拟环境。
若后续采用官方 ROS2 路线，应重新核对上游针对 Ubuntu/ROS 版本的支持。
