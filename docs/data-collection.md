# 茶壶标注、示教数据和备份规范

## 图片标注

使用原始图片分辨率，输出 COCO JSON；bbox 为像素单位 `[x, y, width, height]`。
类别固定为 teapot（1）和 cup（2）。teapot 的 keypoints 顺序为 handle_center、spout_tip；
cup 的 keypoint 为 rim_center。坐标使用原始像素，COCO 可见性 v=0/1/2 分别表示
无法定位、可定位但遮挡、清晰可见；无法确定时使用 v=0，不猜三维位置。
框包围可见物体区域，截断/遮挡情况在标注说明中记录，缺席物体不创建假框。
为相邻帧、同一摆位和同一次拍摄保存共同的 session_id/placement_id，整组划分训练与验证。

图片放 `data/raw/<session-id>/`，标注放 `data/annotations/<session-id>.json`；
保留原始文件，处理后图片另存并记录缩放/裁剪映射。
液位标签待反馈方案验证后再扩展，不能使用杯检测置信度作为水量标签。

## 示教记录

第一项任务为固定位置空壶抓起、抬升、放回。先录 3–5 条完整成功演示检查链路，
再增加摆位/方向；失败片段单独保留诊断标签，不混作成功演示。
相机固定、帧率以实测稳定采集为准，先验证兼容主臂或其他示教输入。

每个 session 记录设备/固件、校准版本、相机键和分辨率、采样帧率、公共关节顺序/单位、
动作定义、茶壶 ID/质量、摆位 ID、任务文字、操作者、采集软件版本。
图像、状态、动作记录同一帧关联与时间来源；动作是实际下发目标，不是未来预测或反馈位置。
SDK 原始电机 rad、公共关节 rad 和 LeRobot 公共关节 deg 必须明确转换。

每条 episode 检查：动作完整、抓持稳定、视频连续、帧/时间单调、关节与动作维数一致、
单位/方向正确、无异常跳变、停止后是否仍有动作。人工标签不等于自动验证。
数据划分按 episode、session 和摆位完成，不将相邻帧分到不同集合。

失败分类固定为：通信、反馈、采集缺帧、视觉/遮挡、抓持滑落、放置错误、碰撞、
人工干预、杯跟踪、水量测量、停流余流；可多选并附原始日志。

## 备份流程

停止采集并 finalize 原生 LeRobotDataset，检查质量与视频；对实际数据还须完成上述人工检查。
当前自动 validate 命令适用于本轮合成数据契约，真实数据接入后再按实际 schema 验证。
复制到新目录并核对源和目标 SHA-256，备份不得覆盖已有目录：

```bash
.venv/bin/python scripts/backup_dataset.py \
  --source data/synthetic-empty-teapot \
  --destination /absolute/path/to/new-backup
```

目标中的 backup-checksums.json 保存相对文件名和校验和；源在复制期间变化会判定失败。
备份应保留原始数据、校准、标注、质量报告和版本信息。
正式采集至少保留原始工作副本与另一块存储上的已校验备份，恢复抽查视频和 episode。
本机 data/backups 的合成备份只验证流程，不构成跨设备备份。
当前没有自动上传原始图片、视频、数据集或检查点。
